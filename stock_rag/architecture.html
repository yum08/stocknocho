StockRAG

RAG-based Stock Market Prediction System — scrapes social media, identifies NSE/BSE stock mentions, analyzes sentiment, and generates AI-powered predictions using Retrieval Augmented Generation.

🐍 Python 🗄️ SQLite + SQLAlchemy 🧬 ChromaDB Vectors 🔍 RAG Pipeline 🤖 Gemini / GPT-4 / Ollama 🧪 136 Tests • 75% Cov

System Architecture

Multi-stage pipeline with two-level database design, vector store, and LLM-powered RAG prediction.

🌐 Data Sources

Scrapes social media via Apify cloud APIs — no personal credentials needed.

  • Telegram — Channel posts, media, reactions
  • X.com (Twitter) — Tweets by handle or search
  • LinkedIn — Profile posts, engagement
  • Extensible — Reddit, YouTube, RSS (add normalizer)

⚙️ Ingestion Pipeline

Normalizes all platforms into a unified schema and deduplicates.

  • Platform-specific normalizers for each data source
  • Deduplication via platform + external_id
  • Supports JSON files, CSV files, and live Apify API
  • Auto-discovers existing scraper output files

🗄️ Level 1 DB — Raw Posts

All scraped posts land here first (SQLite via SQLAlchemy ORM).

  • sources — Channels, handles, reliability scores
  • raw_posts — Unified post schema (text, author, views, likes)
  • scrape_jobs — Track each scrape run status

🔍 Stock Identifier

Maps raw posts to NSE/BSE stocks with multi-strategy matching.

  • Exact symbol match — RELIANCE, TCS, INFY
  • Alias match — RIL → Reliance, SBI → State Bank
  • Company name match — "Tata Motors", "Airtel"
  • Regex extraction — target price, stop loss, action

📊 Level 2 DB — Stock-Mapped

Filtered and enriched data mapped to specific NSE/BSE scripts.

  • stocks — Master list (symbol, ISIN, sector, aliases)
  • stock_mentions — Post↔Stock with sentiment & targets
  • stock_signals — Aggregated signals per stock per window

💬 Sentiment Engine

Rule-based scoring tuned for Indian stock market social media.

  • Bullish/Bearish word scoring with weights
  • Indian market slang — "upper circuit", "FII buying", etc.
  • Negation handling — "not bullish" → bearish
  • Signal aggregation per stock per time window

🧬 Vector Store (ChromaDB)

Semantic embeddings of posts for RAG retrieval.

  • Auto-generates embeddings (sentence-transformers)
  • Cosine similarity search for relevant context
  • Metadata filtering by platform, stock, date
  • Auto-syncs from SQLite on each pipeline run

🤖 RAG Pipeline

Retrieval Augmented Generation for intelligent stock predictions.

  • Queries ChromaDB for semantically relevant posts
  • Enriches with structured signals from SQLite
  • Constructs detailed context prompt for LLM
  • Returns structured JSON with prediction + reasoning

End-to-End Call Flow

Step-by-step sequence from data ingestion to prediction output.

Scrape / Import Data

__main__.py → cmd_ingest() → ingestion.DataIngestionPipeline

Scans the workspace for existing CSV/JSON files (or runs live Apify scrape). Each file is auto-detected by platform (telegram, x_posts, linkedin patterns). Platform-specific normalizers (normalize_telegram_post, normalize_x_post, normalize_linkedin_post) convert raw data to the unified RawPost schema.

Deduplicate & Store in Level 1 DB

ingestion.py → Database.insert_raw_post() → Database.bulk_insert_raw_posts()

Each post is checked for duplicates via platform + external_id unique constraint. New posts are inserted into raw_posts table, duplicates are skipped. The scrape job is tracked in scrape_jobs with counts (scraped, new, errors).

Identify Stocks in Posts

__main__.py → cmd_process() → StockIdentifier.process_unprocessed_posts()

Fetches all unprocessed posts (is_processed=False). For each post, runs multi-strategy matching: Symbol (RELIANCE, TCS) → Alias (RIL→Reliance, SBI→State Bank) → Company Name (partial match). Posts with matches are marked is_stock_relevant=True; creates entries in stock_mentions.

Extract Trading Details

stock_identifier.py → StockIdentifier.extract_trading_details()

Regex extraction of trading signals from post text: Target price ("target 2800", "tgt: 2800"), Stop loss ("SL 2650", "stop loss 2650"), Action ("buy", "sell", "accumulate"), Timeframe ("intraday", "swing", "positional"). Also detects analysis type (technical vs fundamental) by keyword scoring.

Run Sentiment Analysis

__main__.py → SignalAggregator.analyze_mentions() → SentimentAnalyzer.analyze()

Each stock mention without sentiment is scored using the rule-based engine. Bullish/bearish word lists with weights, negation detection, and Indian market slang produce a score from -1.0 (very bearish) to +1.0 (very bullish) with a confidence level. Results are saved to the sentiment_score and sentiment_label columns.

Generate Aggregated Signals

sentiment.py → SignalAggregator.generate_signals() → Database.insert_signal()

Groups mentions by stock within a time window (default 72 hours). Computes: average sentiment, standard deviation, bullish/bearish/neutral counts, technical vs fundamental mention breakdown. Produces a StockSignal with signal strength (STRONG_BUY → STRONG_SELL), predicted direction, and confidence.

Sync to Vector Store

vector_store.py → VectorStore.sync_from_db()

All stock-relevant processed posts are embedded and upserted into ChromaDB. Uses sentence-transformers (all-MiniLM-L6-v2) for embedding generation. Metadata (platform, author, date, stock symbols) is stored alongside for filtered retrieval.

RAG Retrieval + Prediction

rag_pipeline.py → RAGPipeline.predict() → LLMProvider.generate()

Retrieval: Queries ChromaDB with stock-focused search queries, retrieves top-N similar posts.
Enrichment: Fetches latest StockSignal and recent StockMention records from SQLite.
Context Building: Constructs detailed prompt with signal summary, mention details, and full post texts.
Generation: Sends to LLM (Gemini/GPT-4/Ollama) with system prompt for structured JSON prediction.
Parsing: Extracts prediction, confidence, key factors, risk factors, target price, reasoning.

Output Structured Prediction

RAGPipeline.predict() → JSON response

Returns structured JSON: prediction (Bullish/Bearish/Neutral), confidence (Low/Medium/High), confidence_score (0-1), suggested_action (Buy/Sell/Hold), target_price_range, key_factors, risk_factors, conflicting_signals, and detailed reasoning. Also includes a fallback rule-based prediction if LLM fails.

Why SQLite + ChromaDB (Hybrid)?

Use Case SQLite ChromaDB Winner
"Show all RELIANCE mentions from last 7 days" ✅ Fast indexed query ✗ Not designed for this SQLite
"What are people saying about banking sector?" ✗ No semantic search ✅ Embedding similarity ChromaDB
Deduplication by post ID ✅ Unique constraints ✗ Manual SQLite
Aggregated signals per stock ✅ SQL GROUP BY ✗ Not suitable SQLite
Finding similar posts to a query ✗ Only exact match ✅ Semantic match ChromaDB
Structured filters (date, platform) ✅ Indexed columns ⚠ Limited metadata SQLite

LLM Providers Supported

🌐 Google Gemini

Default provider. Uses gemini-2.0-flash model.

  • Fast and cost-effective
  • Good structured JSON output
  • Free tier available

🧠 OpenAI GPT-4

Premium option via gpt-4o-mini model.

  • Best reasoning quality
  • Superior JSON formatting
  • Pay-per-use pricing

🏠 Ollama (Local)

Free, private, local LLM via llama3.1.

  • Completely free & private
  • No API keys needed
  • Requires local GPU/CPU

Extending the System

➕ Add a New Platform

  • Add Platform.REDDIT to enum in database.py
  • Add normalize_reddit_post() in ingestion.py
  • Register in NORMALIZERS dict
  • Add file detection pattern in ingest_existing_files()

➕ Add More Stocks

  • Edit STOCK_MASTER list in stock_identifier.py
  • Or download NSE CSV and call load_stock_master_from_nse_csv()
  • Stocks are auto-seeded on first pipeline run
  • Add aliases for common nicknames / abbreviations

➕ Add a New LLM

  • Subclass LLMProvider in rag_pipeline.py
  • Implement generate(prompt, system_prompt) method
  • Register in get_llm() in __main__.py
  • Set STOCKRAG_LLM_PROVIDER=your_provider in .env
